# PNPtv ui-kit — design-sync notes

## Repo-specific gotchas

- `@pnptv/ui-kit` ships no `dist/` — its `package.json` `main`/`types` point
  straight at `./src/index.ts` ("consumed as source by Vite"). The converter's
  synth-entry fallback handles this automatically; no `cfg.entry` needed.

- **`cssEntry` is a hand-built artifact, not something the DS package
  produces.** The kit's Tailwind classes only exist once compiled through the
  *consuming* app (`apps/web`), which includes `packages/ui-kit/src/**` in its
  Tailwind `content` glob via `@pnptv/ui-kit/tailwind` as a preset. Built with:

  ```sh
  cd apps/web && npx tailwindcss -i src/styles/globals.css \
    -o ../../packages/ui-kit/.ds-cache/entry.css -c tailwind.config.ts --minify
  ```

  `apps/web`'s real `vite build` is currently **broken** — `TypeError:
  manualChunks is not a function` from a Rolldown/Vite 8 incompatibility in
  `apps/web/vite.config.ts`, unrelated to this sync. The Tailwind CLI above
  sidesteps it and produces the same utility classes. If that build gets
  fixed upstream, it's worth re-evaluating whether the full Vite build output
  is a higher-fidelity source than the CLI-only compile (e.g. extra
  autoprefixer/PostCSS passes the real pipeline might add).

  `cssEntry` must resolve **inside `packages/ui-kit/`** (the tool bounds it to
  `pkgRoot`, not the workspace root) — that's why the compiled file lives at
  `packages/ui-kit/.ds-cache/entry.css`, not under the repo-root
  `.design-sync/`.

- **Roboto Mono needed a manual fix.** It's loaded in `apps/web/index.html`
  via an HTML `<link>` tag, not a CSS `@import` or `@font-face` — so it's
  invisible to the converter's CSS scrape and was flagged `[FONT_MISSING]`.
  Fixed by prepending a Google Fonts `@import` to the top of the compiled
  `entry.css` (same pattern the source already uses for "Ethnocentric Rg",
  which loads via a real `@import` in `globals.css` and needed no fix).
  **This prepend must be redone on every re-sync** — regenerating
  `entry.css` via the Tailwind CLI overwrites it. The exact line:

  ```css
  @import url("https://fonts.googleapis.com/css2?family=Roboto+Mono:wght@400;500;600;700&display=swap");
  ```

- **`font-display` Tailwind class doesn't exist in the compiled output**, even
  though `tailwind.config.ts` declares it — nothing in the app or ui-kit
  source ever writes the literal class name `font-display`, so Tailwind's JIT
  never generates it. The display font ("Ethnocentric Rg") is actually
  applied via a bare `h1,h2,h3{font-family:...}` element-selector rule in
  `globals.css`, which **is** in the compiled CSS. Documented in
  `conventions.md` so the design agent uses heading tags, not a font class.

- **Modal capture-harness quirk (not a real bug):** the capture harness
  renders `cardMode: single` stories inside a `transform`-wrapped ancestor so
  `position: fixed` descendants stay contained. Because that ancestor holds
  no in-flow content (Modal's own root is `fixed`), its auto-height is 0,
  which collapses Modal's `inset-0` centering and clips the top of the dialog
  in screenshots. Fixed by adding an explicit-height spacer `<div>` as a
  sibling before `<Modal>` in `.design-sync/previews/Modal.tsx` (see the
  comment there) — purely a harness accommodation, doesn't change what ships.
  Apply the same trick to any future full-viewport `fixed inset-0` overlay
  preview (a Drawer/Sheet component, etc.).

- Badge's `success` and `accent` variants are visually identical in the
  shipped source (both use `badge-gradient badge-gradient-text`) — confirmed
  intentional-or-not by the component code itself, not a preview mistake.
  Worth flagging to the design team if it's not intentional, but not
  something this sync should silently "fix."

## Re-sync risks

- `entry.css` (the `cssEntry` target) is **not regenerated by any build
  script** — a re-sync must manually redo the Tailwind CLI compile + the
  Roboto Mono `@import` prepend above before rebuilding, or the sync will
  either fail (`[CSS_PLACEHOLDER]`/missing file) or ship stale styles that
  don't reflect source changes to `packages/ui-kit/src/*.tsx`.
- No `tokensPkg`, `extraFonts`, or `guidelinesGlob` configured — the kit has
  no dedicated tokens package and self-hosts no fonts. Revisit if a future
  version adds either.
- `apps/web`'s production build (`vite build`) is broken independent of this
  sync (see above) — not this sync's problem to fix, but it means the CSS
  source is one step removed from "the real build output."
